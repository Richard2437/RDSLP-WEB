1. DESCRIPCIÓN GENERAL
----------------------
RDSLP es una plataforma web educativa tipo red social enfocada en lenguajes
de programación. Permite a los usuarios registrarse, iniciar sesión, explorar
contenido de lógica, lenguajes, bases de datos y libros, además de interactuar
en un muro comunitario y participar en eventos.

2. PÁGINAS DEL SITIO
--------------------
  - login.html        → Inicio de sesión
  - sesion.html        → Registro de nuevos usuarios
  - dashboard.html     → Panel principal (inicio, contenido, admin)
  - muro.html          → Muro de publicaciones
  - ejercicios.html    → Ejercicios de programación
  - logica.html        → Contenido de lógica de programación
  - libros.html        → Biblioteca de libros recomendados
  - comunidad.html     → Eventos y comunidad
  - perfil.html        → Perfil del usuario
  - databases.html     → Sección de bases de datos

3. ARCHIVOS JAVASCRIPT PRINCIPALES
-----------------------------------
  - JS/auth.js         → Autenticación, registro, login, roles, ban/unban, salas y eventos
  - JS/dashboard.js    → Lógica del dashboard y panel de administración
  - JS/login.js        → Lógica del formulario de login
  - JS/sesion.js       → Lógica de registro y validación de Habeas Data
  - JS/legal.js        → Módulo legal de Términos de Servicio y Habeas Data (Ley 1581)
  - JS/comunidad.js    → Gestión de salas públicas y privadas con código de invitación
  - JS/api-client.js   → Cliente API para conexión con backend

4. ROLES DE USUARIO
-------------------
  - admin      → Acceso total: gestionar usuarios, banear, cambiar roles
  - moderator  → Permisos intermedios de moderación
  - user       → Usuario estándar con permisos básicos

5. ESTRUCTURA DE DATOS DE USUARIO (localStorage: rdslp_all_users)
-----------------------------------------------------------------
  {
    id:                 número único (timestamp),
    email:              correo electrónico,
    password:           contraseña,
    name:               nombre completo,
    role:               "user" | "moderator" | "admin",
    avatar:             iniciales (ej: "JP"),
    bio:                biografía del usuario,
    isBanned:           false | true,
    habeasDataAccepted: true,
    termsAccepted:      true,

    createdAt:          fecha ISO de creación
  }

6. PRIVACIDAD DE COMUNIDADES Y SALAS (MODELO FACEBOOK / WHATSAPP)
-----------------------------------------------------------------
  a) Decisión de Privacidad por el Creador:
     - Tal como en los Grupos de Facebook o Comunidades de WhatsApp, la persona que
       crea la comunidad o sala es su Administrador y decide la privacidad:
       * 🟢 PÚBLICO / ABIERTO: Cualquier usuario registrado de la plataforma puede
         descubrir la sala, ver su temática, inscribirse libremente y chatear.
       * 🔒 PRIVADO (CON INVITACIÓN): La sala está protegida con un código alfanumérico
         único generado por el sistema (ej: RDSLP-ABC12) o personalizado por el creador.
     - Solo los usuarios que ingresen el código correcto obtienen permiso de acceso.
  b) Gestión y Ajustes de la Sala (Exclusivo Creador / Admin):
     - El creador tiene el botón "⚙️ Ajustes" en la tarjeta de su sala para:
       * Cambiar la privacidad en cualquier momento (de Público a Privado o viceversa).
       * Regenerar el código de invitación con un solo clic si fue filtrado.
       * Modificar el nombre y descripción de la sala.
     - Botón "🔑 Ver Invitación" para copiar el código al portapapeles y compartirlo
       directamente por WhatsApp, Discord o correo.
  c) Permisos Estrictos en Chat en Tiempo Real:
     - Verificación automática de autorización en cada sala: si un usuario intenta
       enviar o leer mensajes en una sala privada sin haberse unido válidamente con el
       código, el sistema bloquea la acción notificando acceso denegado.

7. CUMPLIMIENTO LEGAL Y HABEAS DATA (LEY 1581 DE 2012 / GDPR)
-------------------------------------------------------------
  a) Política de Tratamiento de Datos Personales (Habeas Data):
     - Módulo legal interactivo (JS/legal.js) con el documento legal completo.
     - Declaración de responsable, finalidades legítimas (educativas y comunitarias),
       derechos ARCO (Acceso, Rectificación, Cancelación, Oposición) y canal de contacto.
     - Compromiso expreso: RDSLP NO vende ni cede datos a terceros con fines comerciales.
  b) Términos y Condiciones de Servicio:
     - Reglas de convivencia comunitaria, prohibición de código malicioso o conductas de acoso.
     - Licenciamiento de código compartido para propósitos de aprendizaje colaborativo.
  c) Consentimiento Informado en Login y Registro:
     - login.html: Aviso legal con enlaces para leer Términos y Habeas Data.
     - sesion.html: Checkbox explícito y obligatorio de aceptación sin el cual no se
       permite la creación de la cuenta, guardando la fecha ISO del consentimiento.

8. MEDIDAS DE SEGURIDAD GENERALES
---------------------------------
  a) Verificación de permisos antes de acciones admin (canManageUsers, canManageEvents)
  b) Los admins NO pueden ser baneados por otros admins
  c) Sesión del usuario almacenada separada (rdslp_user) de la lista completa
  d) Evento personalizado "userListUpdated" se dispara tras cada cambio
     (registro, ban, unban) para sincronizar la interfaz del admin en tiempo real
  e) Validación de formularios en el lado del cliente y servidor
  f) Contraseñas almacenadas en localStorage (SOLO DEMO - en producción usar
     hash bcrypt en servidor)

9. PANEL DE ADMINISTRACIÓN
--------------------------
  - Muestra estadísticas: total usuarios, comentarios, eventos
  - Pestañas: "Usuarios Activos" y "Usuarios Baneados"
  - Acciones por usuario: cambiar rol (select), banear/desbanear (botón)
  - Se actualiza automáticamente al registrar nuevos usuarios
